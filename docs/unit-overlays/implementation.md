# 单位名称、提示与生命变化反馈

2026-11-02 按用户要求，去除场景浮层在屏幕边缘向内挪动的行为，选中单位不再扩展属性文字，生命变化改用名称下的细血条。

## 行为与实现

- 人物名称、说话气泡、土地／建筑／资源操作按钮和目标短提示都保持世界锚点。取消左右钳制、上下换边及绕固定控件寻位；超出部分自然裁切，锚点离屏后隐藏。相机拖动、缩放和窗口尺寸变化继续按实际投影定位，不取消选择或指令。
- 同一对象的结果提示固定叠在其操作按钮上方。气泡固定在名称上方，按实际名称高度留出 12 CSS 像素，其中包含气泡尾部；不再移到名称下方。
- 名称保持原文字、领头标识及敌我颜色，删除选中时追加的生命／体力／坐骑属性及休整文字。血条绝对定位在名称底板外，不扩展名称尺寸，不接收输入。
- 血条为 32×3 CSS 像素，名称下留约 3 像素，填充比例来自实际生命状态。人物、敌军、狗和马均接入；骑兵与马分别变化时，在骑兵名称下按需排列对应细条。
- `HealthIndicator` 只维护临时显示状态：首次采样不触发，伤害与治疗会触发并续时，最后变化后 4 个游戏秒隐藏。选择、体力消耗或重载已有伤势不触发；设置和后台暂停停止游戏时钟，暂停不改变血条期限。当前尺寸与持续时间是可调整的表现参数。
- 继续使用现有 0.25 游戏秒的界面刷新，DOM 元素复用，仅值或显隐变化时写入。没有新增模型、Canvas、渲染通道或墙钟定时器。固定 HUD、安全区和居中的系统面板继续采用既有布局。

入口为 `src/ui.ts` 的 `positionOverlay`、`positionSpeech`、`setUnitHealth`，人物投影在 `src/game/residents.ts` 的 `updateLabels`，生命状态由 `src/game/game.ts` 的 `refreshEconomy` 传入。

## 验证

`npm test`：164 项逻辑测试通过，包含初次／存档采样、伤害、治疗、独立骑手／马匹、零生命以及按游戏时间暂停／消退。

类型检查和生产构建通过。5 个相关桌面／手机浏览器场景分批复测后全部通过，运行实际 Babylon 场景并检查真实 DOM 投影、触控、进食回血及战斗：

- 桌面：四边名称位置、离屏隐藏、选择保持、回血细条尺寸、名称宽度不变、暂停超过 4 秒不消退、恢复后正常隐藏。
- 手机：狗、骑手及马匹进食回血、独立细条、手动移动覆盖休整，以及士兵受伤反馈。
- 手机及矮屏：领头停止发言、名称与气泡尾部间距、设置居中和模态输入隔离。
- 320 像素窄屏：操作按钮和短提示保持原锚点并裁切，直接点击露出的按钮仍可安排作业；从空白地图往返拖动后，作业和多按钮布局正常。

新增断言初次遇到离屏进食动物、已退场敌人，以及拖动起点落在操作按钮上的情况；已按实际可见目标、存活受伤士兵和空白地图触控修正测试，并等待真实投影帧后测量短提示。最终成功记录见[验证摘录](evidence/verification.txt)。本轮执行上述相关场景，未运行整个历史 E2E 集合。
