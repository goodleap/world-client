# 区域地图与内容扩充

2026-11-01。接续 d4394d9，在远端最新 main 基础上实施；设计位于 world-design 的 `玩法设计/地图/区域地图与探索.md` 与 `数值设计/区域探索试行参数.md`。

## 可玩内容

- 9 块活动区域，两个主要回环和两条尽头支路；按 1 引擎单位采样约 70% 地表不可通行。当前外框仍为 100×100 试验格，行列与区域、连接配置分开；没有把 100 固化为长期设计规则。
- 家园、林间营地、果丛采集区、矿谷、东岸草甸、南部沃地、山口、石坳和东南林地。建设须在允许的完整空地内，并保留通道。景观树不再全部作为可砍资源，砍树不会破坏地图边界。
- 当前 39 个木材点、28 个石材点、11 个果丛、10 个铁矿点；采集产物必须搬运入库。资源以保存的游戏时刻恢复，避开建筑、农田和实时人物占位。
- 仓库可加工工具与装备；使用实际农民作业、材料预留、单次扣费、共享强化，所有已建成仓库均可加工。工具增加工作速率；装备作用于实际攻击与护甲。试行数值列在设计仓库。
- 矿谷、山口独立守卫与奖励；山口包含重卫，东岸有巡逻；重卫暂复用现有步兵外观，通过名称与属性区别。已占领建设区保持安全；巡逻按游戏时间、己方人员和建筑距离条件补充，每批奖励进入普通运输流程。
- 保持单兵点击移动/攻击、自动进食、火堆配送和暂停规则。存档升级至 v9，不迁移旧地形存档；存档检查不会自行清除旧档。

## 实现选择

Babylon.js 9.32.1 的 Curve3、ExtrudePolygon、原生实例化、既有角色 LOD 与 AnimationGroup 继续负责显示。新增 `polygon-clipping` 做加载时的二维区域布尔合并；Babylon 多边形构建使用 `earcut` 三角剖分。引擎的网格绘制不提供区域用途、通道保留或连续身体碰撞规则，因此将同一多边形数据提供给现有连续导航/碰撞体系；不增加每帧 CSG、实时反射或额外灯光。

静态阻隔分成约百个粗空间块，利用既有多边形包围盒快速排除远处地形。保留一次生成的场景树、颜色贴图、静态台地与共享树木 LOD。密林台地接收树影，自身不投射大平面自阴影，解决首轮实际渲染出现的条纹。缩远隐藏未选中人物名称，避免总览文字堆叠。

视觉参考为用户本轮区域草图及设计仓库的植物/资源原型图；原型树、建筑、人物和动作继续复用既有来源。果丛以参考灌木的饱满叶簇体积制作，铁矿以现有岩石形体加矿脉顶点色表现。没有新增重复人体、角色骨架或公共动作文件。

## 验证记录

最终结果另见 [verification.json](verification.json)：类型检查与 Vite 构建通过，156 项逻辑测试通过，8 个相关浏览器场景经分批执行与必要修正后全部通过；没有宣称运行全部历史浏览器用例。浏览器使用 `/usr/bin/chromium` 与 SwiftShader，桌面 1280×900、模拟 Pixel 7 竖屏，串行运行。

逻辑覆盖每个区域的步兵/骑兵路线及沿途碰撞、道路/密林禁建、独立占领、铁矿运输与加工成本、取消与重载、生产/战斗强化效果、资源恢复与占位、巡逻实际往返与延迟补充、奖励防重发。既有战斗、体力、火堆、共享角色与经营回归保持通过。

浏览器覆盖真实鼠标/触控的单兵连续移动及途中保存恢复、骑兵/弓兵攻击和独立指令、矿谷清理与奖励保存、矿区采矿→区域仓库入库→加工→暂停→重载，以及手机果丛按钮与密林禁建。采矿场景以已经占领矿谷、建有区域仓库为前置存档，后续采矿与运输均通过实际输入和游戏导航完成。

首轮加工测试曾将农民摆在矿石正前方，点击被人物挡住，没有产生采矿任务；调整测试站位后重新验证。旧地图中的火堆测试位置现在属于保留通道，相关前置位置迁入合法空地。没有降低碰撞或建造规则来让旧坐标通过。手机相机测试辅助函数曾将小于拖动阈值的尾段当成点击；跳过这段不足 10 像素的微调，并按实际镜头投影点击后，手机采集/禁建验证通过。

已实际查看全图、家园、果丛、铁矿/仓库加工及桌面/手机布局截图；截图保存在本目录。云端软件渲染的帧率、响应时间和视口模拟不代表真实 iPhone 性能。全图提交成本仍高于日常局部视角，真机持续游玩、发热与性能仍需后续验证。

## 本批次边界

食物新增采集来源，继续复用农田；野兽狩猎、新动物、新锻造建筑尚未制作。铁矿加工采用仓库共享强化，未实现单件装备/背包或独立铁锭库存。环路为现有可绕行道路，没有“清理后生成桥梁/打开山门”的机关。未增加家园防御，敌军主要与参战士兵交战。全图为固定布局，无随机世界与战争迷雾。
