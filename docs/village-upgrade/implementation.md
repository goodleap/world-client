# 2026-11-03 加载、经营与士兵成长

本批对应用户明确授权的七项修改，基于游戏仓库 `55c8879`、设计仓库 `26a292f` 的最新 main 开发。前批角色移动、骑兵半径 0.6、步兵／弓兵半径 0.4、哨塔生命 500／防御 20 继续保留。

## 功能

- 手机加载：移除蒙皮克隆不需要的逐顶点拾取缓存，并省去运行时永久隐藏的旧人物／马匹占位网格。保留正式 GLB、几何共享、独立骨骼与动作、LOD 和姿态包围盒。
- 耕地：四个方形种植床与中央十字田埂，作物分布在四块中；占地、作业数量、投入和产量沿用原规则。
- 敌方骑兵：混编营地在原人数内替换 1～2 名骑兵，敌兵来袭从第 4 波起包含 1 名；复用骑手／马匹资源和现有战斗流程。
- 敌我士兵等级：实际扣血 1 点记 1 经验，保留小数、排除过量伤害；累计 200／600 经验升至 2／3 级，最高 3 级。生命、攻击分别增长 10%／20%，防御增加 1／2，再加我方装备固定加成；已有伤口保留。家园人口显示等级与本级经验。
- 点选：农民、步兵、弓兵、骑兵、狗分别使用直径／高度 1.4/2、1.6/2.3、1.5/2.2、1.8/2.8、1.3/1.2 的直立圆柱；建筑用实际范围的长方体，火堆用石圈直径 2.68、高 1.6 的低圆柱。点选体积与物理碰撞、攻击接触距离独立。
- 家园建筑：没有维修需求时隐藏维修按钮；顶部自动维修开关默认关闭，开启后为已有及后续受损建筑安排维修。单建筑不重复排队，材料不足等待，危险区不自动派工，关闭后保留可单独取消的已有任务。
- 危险区域：所有任务共用空间危险记录，检查目标、完整去程和回仓路径，能绕行则绕行；进食和个人补给同样执行。移动威胁留下短时区域记录，连续安全 10 游戏秒才解除，遮挡或改任务不清除记录；暂停保存材料、进度和实物，其他安全工作继续。

当前存档格式为 v19，保存经验、自动维修、危险区域和清场时间；按项目约定不迁移旧版本。

## 加载问题的证据

未找到应用主动反复刷新的代码。实际分配采样定位到 Babylon 9.32.1：蒙皮 `Mesh.clone` 刷新包围盒时经 `_getData` 创建逐顶点 `Vector3` 拾取缓存，多个角色重复持有，采样中约 1,021 MiB 来自此调用链。这是手机加载阶段明显的内存风险；没有把桌面浏览器测量说成已经捕获了用户手机的崩溃日志。

采用引擎公开的 `Geometry.releaseForMesh`／`applyToMesh` 和同步 `onClonedObservable`，重新绑定同一几何以释放无用位置缓存，并恢复原姿态包围盒。没有修改引擎私有字段、丢弃顶点数据或降低角色模型质量。

| Chromium 手机视口新游戏 | 修改前 | 本批最终版本 |
| --- | --- | --- |
| 加载阶段 JS 堆峰值 | 1,632,495,964 字节 | 390,516,780 字节 |
| GC 后 JS 堆占用 | 1,573,571,180 字节 | 306,782,936 字节 |

最终场景有 107 个角色，其中敌方骑兵 14 名，无页面错误。峰值降低约 76%，GC 后降低约 80%。数据见 [loading-memory.json](loading-memory.json)；字节数只代表浏览器 JS 堆，未把软件 WebGL 的 FPS 或不同并发负载下的加载时间当成手机性能结论。

复测命令：`LOAD_REVIEW_URL=http://127.0.0.1:5175/ node tools/review-load-memory.mjs`，开发服务或显式 E2E 构建提供只读场景诊断。
