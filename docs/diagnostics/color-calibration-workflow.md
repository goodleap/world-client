# 原型色彩的计算与原生引擎校准

此工具把“先取样、固定环境、计算初值、自动拟合、最后视觉检查”落实为可重复流程。不会自动修改游戏材质，也不把单张图片的最终像素直接当作模型基色。

1. 在私有设计仓库为指定原型记录代表区域：材质、对应网格、原型区域边界、亮／中／暗部取样矩形。原型图留在设计仓库。
2. `extract_reference_palette.py` 读取 PNG，记录图像校验和、区域中位 RGB、像素范围和取样数量。当前无嵌入 ICC 的原型按 sRGB 解释。
3. 固定实际模型、Walk 首帧、正面相机、游戏 daylight、曝光、色调映射及分辨率。使用 Babylon 9.32.1 的 `RenderTargetTexture` 与原生 `readPixels`，渲染实际 PBR 材质、蒙皮和顶点色。
4. 从线性颜色比例计算初值，再在合法线性基色 [0,1] 内进行有界坐标搜索。误差为区域中位色的 D65 CIELAB ΔE76；没有另写一套着色器近似引擎输出。
5. 保存输入、环境、基准值、候选基色、各区域误差、参数是否碰到边界和评估次数。只在开始和结束保存实际画面，供关键节点审查。

云端运行示例（Python 环境需要 Pillow）：

```sh
node tools/review-server.mjs
python3 tools/extract_reference_palette.py /workspace/world-design/角色原型图/基础人物色彩目标.json
node tools/calibrate_character_colors.mjs /workspace/world-design/角色原型图/基础人物色彩目标-sampled.json
```

工具当前针对基础人物、正面、游戏日光；不支持的配置明确拒绝。默认结果写到云端 `/workspace/artifacts/color-calibration/`。原型区域按轮廓归一化映射到模型区域，属首轮近似；若与背景相交过多会报错。量化阶段隔离材质并关闭自身投影，正式采用前仍需真实游戏光照、阴影、侧面、动作和手机显示审查。

首轮实际结果：头部平均 ΔE76 为 10.50，搜索没有找到改善；其材质基色已经是 [1,1,1]，实际肤色还由顶点色控制。棉布从 10.24 降到 7.29，但参数碰到边界，三个区域仍有明显残差。这些是代表区域的指标，不是整体还原评分。

因此本轮候选没有写入游戏。后续应结合顶点色、主光方向、补光比例、材质响应、形体/法线及区域对应关系解释差异。固定其余条件时，一个基色不能独立控制亮部、中间色和暗部；不能通过无限重复改同一个色号来宣称解决。原型取样、完整运行记录与候选图保存在私有设计仓库。
