# 基线测试复核（2026-11-09）

前次完整检查中，原有 393 项测试有 14 项失败，均可在 `b4ca741` 基线上复现。逐项复核后，既有过时的测试场景，也有三个真实实现问题；没有跳过或删除失败用例。

## 实现修复

1. **导航障碍分批更新**：Detour TileCache 除了 64 个障碍请求，也只有 64 个待更新区块。原先每 48 个障碍统一更新时，分散的树石会触及更多区块，部分障碍虽然登记成功，却未刻入导航网格。现在每 8 个请求调用原生 `WaitForFullTileCacheUpdate`，兼顾单个障碍最多触及 8 个区块的上限，添加和移除都采用同样规则。保持原有角色尺寸、地形、寻路和扫掠校验。
2. **箭矢存档世界高度**：旧校验只接受 0～10 的高度，拒绝了矿谷等低洼地形上的合法箭矢。现在接受有限的 -5～35 世界高度，覆盖当前地形与塔台；继续拒绝越界值、非数字、无效目标及重复投射物。没有旧存档迁移。
3. **缩放地形锚点**：缩放前先拾取实际地形，缩放后用 Babylon 原生 Ray／Plane 求原锚点高度上的投影，再调整镜头位置。避免第二次拾取落在另一层台地时产生高度差偏移；缩放比例、上下限及相机半径保持原规则。

导航原因已对照安装版本的 TileCache API 文档，以及 [DetourTileCache.cpp](https://github.com/recastnavigation/recastnavigation/blob/main/DetourTileCache/Source/DetourTileCache.cpp) 的请求处理与更新队列实现。继续复用 Babylon Navigation Plugin V2、Detour 及官方缓存更新接口，没有引入替代寻路器或新依赖。
