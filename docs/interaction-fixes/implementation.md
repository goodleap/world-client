# 2026-11-03 据点追击、灰狼点选与就近移动

本批依据用户讨论后明确的「开始改」实施，基于游戏 `e1796d4`、设计 `3cea265`，没有回退此前移动、等级、维修或危险区域功能。

## 行为与原因

1. 据点守卫原先在目标或自身越过营地边界时立即清除目标、返回哨位，贴脸对手也会被忽略。现在保留 8 单位警戒和固定营地锚点，在原追击边界之外增加 6 单位缓冲。已有目标在可见近距离（3 与实际武器射程的较大值）继续交战；离开原追击范围且不再保持近距离接触时，连续 3 游戏秒没有实际伤害来往才回营。任一方超出最终营地距离上限则直接开始回营。脱战计时保存并随暂停冻结。
2. 回营保留原哨位目的地，最多在 3 单位内按原武器射程反击，冷却或对手离开后继续走，不追出去、不更新锚点。复用正常攻击的接触预测；预计挥击时够不到的跑动对手不会让回营者无故停步。没有扩大射程、恢复生命或修改攻击频率。
3. 灰狼可见网格一直设置为不可拾取，却没有人物那样的独立点选体；原生拾取过滤因此排除了它。补上直径 1.6、高 1.5 的低圆柱，跟随插值后的狼根节点，原生射线识别后进入现有攻击指令。独立于三档 LOD、逐顶点缓存及模型网格，对象池换绑更新 ID，死亡、退场、空槽关闭拾取，物理半径仍为 0.72。
4. 手动移动点击附近的候选半径从 3 扩至 6 世界单位，原点击仍最优先；按离点击点的距离排序，在可达连通区域内选择落点，再沿原扫掠检查细化。复用一次 A* 的可达区域，不逐候选重复寻路。终点、反馈和保存都使用实际接受点，完全不可达时保留原命令。作业接近和进食座位仍要求精确到位。

## 验证方式

逻辑测试覆盖三种守卫跨旧边界继续造成伤害、3 秒计时与受击续期、保存／暂停、最终距离限制、回营自卫与跑动对手；原有移动目标追击、哨塔、狼群、危险区域和导航队列回归同时检查。原生 NullEngine 射线验证狼圆柱拾取、目标 ID 换绑、禁用和父节点退场；寻路验证 3～6 单位外的可达落点、身体尺寸、完整扫掠路径和精确作业点。

浏览器工具 `tools/review-interaction-fixes.mjs` 在临时拦截的开发响应中控制每次推进 1/60 游戏秒，实际使用 Babylon、正式 GLB、原生鼠标／触控事件和游戏逻辑。记录连续每帧并生成 60 帧视频；这不是硬件帧率测量，审查工具的控制入口不进入产品构建。

重现：启动 `npm run dev -- --port 5175 --strictPort`，运行 `node tools/review-interaction-fixes.mjs`。可用 `INTERACTION_REVIEW_CASES=camp-mobile,defence-mobile,wolf-mobile,fallback-mobile,wolf-desktop` 选择场景；输出默认在 `/tmp/world-interaction-review`。工具使用 Playwright、系统 Chromium 和 FFmpeg，可通过环境变量指定浏览器路径、服务地址与输出目录。
