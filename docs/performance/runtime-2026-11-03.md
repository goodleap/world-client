# 手机渲染与精简诊断：第一批

用户于 2026-11-03 授权优化此前只读检查发现的问题，并要求一次复制即可定位主要性能开销。

- 选中反馈改用 Babylon 原生 OutlineRenderer，只提交选中模型的轮廓，保留蓝色脚圈、建筑范围和原生拾取。去掉 HighlightLayer 的全场遮挡绘制、模糊及合成；轮廓宽度 0.01，近远 LOD 均跟随原骨骼。
- 使用 Babylon 原生 selection octree（容量 32、深度 4）。冻结且不可变的物件进入树；人物、门、隐藏实例模板和可变 Thin Instance 范围保留动态路径；备用 LOD 不独立进入候选集合。新增/移除 Mesh 后重建，另用数量检查覆盖 Babylon 延迟发送新增事件的同帧空隙。没有冻结整个活跃集合，也没有改变游戏逻辑。
- 自动保存由“每次状态 revision 改变就同步写入”改为每 5 个游戏秒合并一次。明确操作保存、设置暂停、后台及离开立即刷新，失败后间隔重试。记录写入次数、字符数、实际耗时与失败数。
- 默认复制使用 schema 2 紧凑 JSON：构建提交、设备、当前画质/限帧/分辨率、最后运行样本自身的画质/选中/相机上下文，主画面/阴影/选中轮廓的实际绘制计数，LOD 档位汇总，十秒 min/mean/max、至多六个趋势点及三个慢帧。慢帧保留逻辑、世界同步、存档和场景提交耗时；不可测 GPU 保留 null。
- 加载日志合并解析和逐单位装配，保留三个最慢下载、失败/未完成详情；代码与资源分别记录跨度，避免把主菜单等待或重新开局之间的间隔称为加载耗时。bodyBytes 是资源内容大小，不等于网络传输量；未知缓存状态不会推断为命中。
- 暂停后保留最后运行采样；设置内重画和画质切换不覆盖它。当前设置和历史采样上下文分别保存，避免把 20 帧限帧样本误认成设备性能上限。

## 测量和边界

Chromium / SwiftShader，393×754，DPR 3、实际缓冲区 589×1131。运行中同视口选中步兵的采样：原实现 514 draws / 2,700,378 triangles，新实现 378 draws / 1,980,298 triangles，其中选中轮廓单独 30 draws。未选中约 347 draws；候选 Mesh 约 800，相比场景约 1950 个。居民与作物继续运行，所以这些是现场采样而非完全相同动画相位的像素基准，也不是 iPhone FPS 或功耗收益。

复制的完整日志约 4.2 KB（此前用户日志含几十条重复加载项和二十条完整性能行）。上下文、各通道加总、暂停切换保留样本和保存重载由桌面/手机生产构建浏览器回归覆盖。原生阶段计数适配 Babylon 9.32.1，升级时须复核 OutlineRenderer 的前后 stage；不替换底层 draw 函数。
