## 动画复核与骑兵卡顿

两处不同问题：人物死亡此前只在 50 ms 逻辑步采样，灰狼虽然每帧调用但也使用离散逻辑时间；骑兵首次倒地还要为骑手展开姿态做 25 轮 CPU 蒙皮读取、遍历顶点，阻塞死亡所在帧。

现在死亡仅在表现层使用插值游戏时间。骑兵模型加载时生成接地曲线，同库骑兵共用只读曲线，每名仍拥有独立原生动画及骨架；加载后恢复原父节点和活体姿态。运行时死亡直接复用数据，不把接地计算放回战斗帧。该准备在真实加载进度中单列，精简日志归为装配；计算工作移到加载阶段，并未消失。

| 动画 | 复核结果 |
| --- | --- |
| 人物／狗／坐骑移动、转身 | 保留 RenderMotion 插值与原生每帧骨骼播放，取消体力速率系数。 |
| 人物待机、农民敲击、狗行走／跑／进食 | 原生动画组按场景时钟播放，暂停停止，屏外恢复保留相位；没有把逻辑步长直接当作每帧动画时间。 |
| 挥剑、拉弓、刺枪、狼咬／受击／进食、箭矢 | 保留插值采样，伤害仍由逻辑步结算；狼待机原来锁在第 0 帧，改为按原生 Idle 长度连续循环。 |
| 倒地、停留、下沉 | 农民、敌我士兵、狗、狼、骑手及马均按插值时间采样；0.6／2／3 秒时长不变。 |
| 房门、仓库门、火堆 | 开合与火焰起伏改在渲染帧推进；运输、燃料和进食仍由原逻辑结算。 |
| 移动／攻击内收箭头、路线带、攻击标记 | 原生箭头动画保留；目标跟随插值后位置，路线淡出和攻击标记使用插值时间。 |
| 相机、界面 | 相机继续按渲染时间更新；生命、库存、作业阶段仍显示真实离散状态。 |

`node tools/review-death-cadence.mjs` 在真实 Babylon 游戏中控制 60 Hz 输入、保留 20 Hz 逻辑，连续渲染 352 帧。农民、步兵、弓兵、骑兵、敌军、狗、狼各有 **33/33 个倒地相邻帧、179/179 个下沉相邻帧**姿态变化，最后全部消失；暂停姿态完全一致。实际死亡期间骑兵蒙皮读取为 **0**，加载准备在本次云端运行约 649 ms。检查了实际连续序列，骑手俯卧、马侧卧与分离接地保持，没有整个骑乘模型一体侧翻或悬空。

## 当前限制

入口到平台继续采用位置切换，尚无爬梯动作。除自有塔身豁免外，射线遮挡沿用保守地面平面规则。云端 Chromium 软件 WebGL 的加载耗时与帧率不能代表 iPhone／微信；200 是人口规则上限，不是手机同时密集显示 200 名骨骼单位的流畅度承诺。
