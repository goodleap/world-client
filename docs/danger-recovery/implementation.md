# 农民与狗避险恢复修复

基于客户端 `1918519`、设计仓库 `99bb6ac`。修复旧危险区不解除、个人等待重复叠加，以及狗在避险点无法返回的问题。

## 原因与处理

1. 旧区域续期曾使用「区域半径＋敌人完整警戒半径＋缓冲」。狼离开约 30 单位，或者守军回到营地，仍能隔空续期家园旧标记。现在只以敌人实际位置是否进入旧区域及 2 单位边缘缓冲续期；当前敌人的完整警戒区和固定营地仍保留。连续安全 10 游戏秒、敌人返回重新计时的规则不变。
2. 冷却中的区域曾不断将个人 `safeAt` 更新为当前时间＋5 秒，造成区域等待结束后还要再等。现在删除个人恢复计时，区域解除立即触发恢复检查；人物已经到达区域外时可领取其他安全工作，目标与完整往返路线仍检查所有危险区。离开区域时按实际碰撞半径另留 0.05 净空，避免中心刚越界就被停下、身体仍与路径规划中的危险障碍重叠。
3. 狗只接受能直线走到的漫步目标。避险点附近有人或建筑遮挡时，即使有绕行路线也会一直停住。现在优先选择直达目标；24 次有限采样均无直达目标时，可尝试一个可站立的绕行目标，复用现有路径规划与碰撞跟随。目标、完整路线和后续局部避让都包含共享危险区；失败等待 1～1.5 游戏秒，不逐帧重复规划。

本次继续使用既有 `planWorkApproach`、路径规划和 `stepRoute`，没有增加导航库或第二套移动控制器。Babylon 负责已有的模型、动画与渲染插值，危险区域属于游戏规则；重新引入导航网格并不能修复区域续期和计时错误。

## 验证

相关 57 项逻辑测试通过，覆盖旧区域释放、实际敌人仍危险、边缘返回重新计时、完整身体脱离区域、中途路段危险、保存重载、暂停、作业与搬运物保留、进食安全、手动指令优先、狗绕障碍与限频重试。类型检查和生产构建通过。

node --test --test-isolation=none tests/danger-recovery.test.ts tests/wander.test.ts \
  tests/demolition-danger.test.ts tests/raids.test.ts tests/campfire.test.ts
npm run build
npm run dev -- --port 5176 --strictPort
node tools/review-danger-recovery.mjs

实际 Chromium 场景使用营地守军原有位置，并留下其曾经过家园的旧危险标记。在第 9.5 秒保存重载，安全计时保持原起点；第 11 秒旧区域已解除，三名农民重新自动接取原先暂停的播种任务并奔跑前往，最终三项播种全部完成。狗在危险区冷却时不会返回，清场后从实际复现的阻塞位置绕行回到活动范围。

为隔离恢复行为，场景关闭管家新增任务，但保留队列的自动领取与执行。测试脚本只通过 Vite 响应向测试页面注入场景读取与时间控制入口，产品代码不包含测试入口。逻辑快进用于设置检查时刻；运动片段逐帧调用正式渲染循环，以每帧 1/60 游戏秒推进固定步长、插值和原生动画，并连续保存画面。

最终版本分别记录农民与狗各 150 个连续渲染帧，并检查画面序列。三名农民的运动位置与原生姿态持续推进，到达后正常进入作业；狗沿障碍侧面绕行，没有停留在原避险点。每段运动中的位置推进比例均超过 98%，姿态在全部运动采样对中变化；初始渲染插值建立阶段不作为停顿缺陷。具体见[逐帧统计](motion-summary.json)、[农民画面序列](farmers-sequence.png)和[狗画面序列](dog-sequence.png)。

当前存档版本更新为 20，删除个人 `safeAt`。沿用开发阶段不兼容旧存档的约定；版本 20 的危险区起点、任务暂停、人物位置及避险状态已检查保存重载。
