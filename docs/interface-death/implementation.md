## 加载诊断及改进

旧主进度仅由居民装配回调驱动，最初 20% 内包含下载、三个共享 GLB 解析和材质批处理；即使内部记录已有字节与阶段信息，也不驱动主条。同一渲染帧里连续处理多个角色，浏览器可能只画出最后一个值。缓存仅避免部分网络传输，仍需重新解析、装配和准备 GPU 资源。

本环境首次基线：共享高模约 21.16 MB、两档 LOD 约 6.67/3.18 MB、狼约 2.70 MB；本地传输很快，20→90% 约 1.82 秒，90→98%（纹理/着色器/场景就绪）约 6.76 秒。第二次同上下文启动：20→90% 约 2.66 秒，场景就绪约 5.06 秒。云端软件 WebGL 数据不是手机网络或真机帧率。

主条现直接订阅真实事件，模型下载按构建时文件大小和实际已收字节汇总，解析按四个 GLB 的完成、材质按三个容器完成、装配按每个角色动作和 LOD 的完成，场景按原生 mesh/texture ready 数量推进；最后通过 scene.whenReadyAsync 与首帧确认。代码请求仍由浏览器原生 import/modulepreload 管理，下载中字节不可读取时明确说明。权重划分为引擎8、地图12、模型下载25、解析20、材质5、角色20、狼实例4、场景就绪5、首帧1；它是完成度，不预测耗时。

CPU 阶段之间让浏览器实际绘制已完成进度，再进入下一批；没有假计时器、定时递增百分比或提前完成。百分比显示到 0.1%。现有诊断保留每项耗时和网络 Resource Timing；一个不可中断的原生 GLB 解析阶段仍可能短暂停留，但会显示正在解析的具体资源。
