# 建筑防御、维修与编队寻路

后续参数更新：哨塔现为生命 500、防御 20，详见[本批记录](../movement-continuity/implementation.md)。下文数值与验证记录对应当时提交。

2026-11-03。对应用户本轮六项要求，一批提交；存档 v16，不迁移旧版本。

## 实现

- 建筑使用统一生命和比例减伤 `max(1, attack × 20 / (20 + armor))`。民房 600/8、仓库 1000/12、家园中心 1500/15、哨塔 500/10、火堆 200/2（生命/防御）；农田不作为建筑目标。友军伤害被排除，建筑归零会清理攻击目标和在途箭。
- 家园增加“建筑”页签，每座一行显示生命、防御、状态、维修报价与操作。场景点击建筑也有生命、防御和维修入口。手机窄屏和矮屏使用可滚动表格。
- 农民实际赴建筑旁维修，复用既有敲击动作和任务系统。工时 8 游戏秒；费用按下单缺损比例向上取整，预留后完工才扣除。中断与重载保留进度和报价；施工中新增损伤不由旧报价免费恢复。取消释放预留，完好建筑不能维修。
- 哨塔归零仍倒塌并结算原有坠落伤害；其余建筑归零留址、停用、可修复。中心暂停招募；仓库停止收货和加工，库存与容量保留；火堆熄灭。运输途中的仓库损毁会改送可用仓库，没有可用仓库则保留实物。不会在损毁的旧门口直接入账。
- 编队中心标记采用真实点击点，槽位按全队实际平均位置居中，修复 5 人等不满行的偏差。各人受障碍限制时仍会按原有半径 3 的规则选择附近可达位置。
- 新增北林、西谷、南坡、东林四组远处营地，各 4 人（重卫 1、近战 2、弓手 1）。复用现有模型、动作和 LOD；每营地不重生，战利品只结算一次。出生点均做身体碰撞及家园可达性检查。敌袭出生和狼群返程同时避让已有驻军，防止新营地堵住退场。

完整试行参数见设计仓库[建筑属性](https://github.com/goodleap/world-design/blob/main/数值设计/建筑属性.md)及[统一目标与路径反馈](https://github.com/goodleap/world-design/blob/main/玩法设计/战斗系统/统一目标与路径反馈.md)。

## 远距离引导延迟

原点击处理器逐人同步执行 A*，然后才显示首位成员的落点标记。云端 Node 测例 `(-4,-4) → (45,55)`，身体半径 0.4，原规划约 267 ms；整队重复计算会连续阻塞主线程。

本次复用既有障碍、扫掠碰撞和最近可达点规划器，将手动点击寻路放入浏览器原生 Worker。Babylon 继续承担拾取、动画、网格与渲染；换用导航网格插件需要重做动态障碍及现有落点语义，此处没有更换整套导航。A* 待访问集合使用稳定最小堆，碰撞先做包围盒排除，仍保留精确检测。

点击处理器先显示单人目标或编队中心反馈；代表成员先计算和采纳真实路线，其他成员随后计算。主线程采纳前重新检查实时位置、整条路线和终点预约，失效时最多重试一次。快速改令覆盖旧请求，死亡拒绝结果；暂停／后台保留结果，恢复后才采纳。已接受路线按原规则保存；尚未接受的 Worker 请求不写入存档。

同编队后续成员先尝试复用已接受的通路，替换为自己的起点和槽位，按自己的体积、全部线段和当前终点预约验证；失败才重新搜索。骑兵不会直接套用步兵可过的窄路。用 `node tools/benchmark-navigation.mjs` 在同一地图、5 个起点和落点上对比，三轮独立规划为 1210～1255 ms，复用规划为 195～295 ms，详见 [planning-benchmark.json](planning-benchmark.json)。这是当前规划器有无通路复用的计算对比，包含云端负载波动，不是对用户设备的帧率预测。

只用真实路径显示引导带，不用假直线或动画进度掩盖计算。自动作业和战斗内部重规划仍是同步调用，本次改善范围是用户点击移动；新营地不代表移动设备可以无限增加单位。

精简日志增加 `navigation`：`pending`、`completed`、`lastMs`、`maxMs`、`workMs` 和 `failed`。端到端等待包含排队、计算和恢复等待，Worker 时间单列，不混入 GPU 时间。

## 验证

- 类型检查通过；生产构建包含独立导航 Worker，沿用现有资源分包。Babylon 引擎大分包仍有原有 Vite 提示。
- 257 项逻辑测试通过，包括建筑防御、维修报价/材料/进度/重载、追加损伤、取消、损毁停用、运输改送、哨塔倒塌、狼群撤退、Worker 过期结果、实时路线与通路复用校验、1～6 人编队中心及新增营地可达性。
- 桌面、DPR 3 手机浏览器实际验证了建筑表格、320 宽度、844×390 矮屏、维修下单/暂停/重载/完工只扣一次，以及远距离 5 人编队的点击中心、真实引导和计算期间持续渲染。
- 4 个针对性浏览器用例通过：桌面及手机建筑/编队、家园招募/编队回归、手机附近可达点/引导回归。另实际点击场景民房下单维修，并查看北林营地的 4 名驻军，未出现浏览器运行错误。

渲染记录：[桌面建筑页](desktop-buildings.png)、[320 宽手机](buildings-320.png)、[844×390 横屏](buildings-844.png)、[桌面编队](desktop-group-destination.png)、[手机编队](mobile-group-destination.png)、[场景维修](repair-in-world.png)、[北林驻军](north-camp.png)。场景检查数据见 [scene-review.json](scene-review.json)，可用 `tools/review-buildings-navigation.mjs` 配合 E2E 生产构建复查。

浏览器端到端数据：[桌面](desktop-navigation-timing.json)、[手机](mobile-navigation-timing.json)。云端软件渲染仅约 3～6 FPS，测得首条真实路线约 1.1 秒、全队约 2 秒；点击标记在事件处理时立即显示，期间继续渲染。CPU 规划与排队、浏览器调度分别记录，不把这些数据当作真机延迟承诺。

浏览器为云端 Chromium/SwiftShader，手机触控和 DPR 是模拟；可证明行为、布局和主线程不被整队同步寻路占用，不能代替 iPhone/微信真机帧率、耗电或热状态。
