# 单兵操作与自主供餐调整

2026-11-01，接续火堆与体力首轮。按最新确认规则取消右下角整组战斗按钮；人物自行解决附近进食及补给。设计主文档：[体力与进食](https://github.com/goodleap/world-design/blob/main/玩法设计/基础经营/体力与进食.md)，参数：[体力与进食试行参数](https://github.com/goodleap/world-design/blob/main/数值设计/体力与进食试行参数.md)。

## 实现

- 修复真实点击空地后士兵不动：Babylon `Vector3.x/z` 为访问器，旧代码展开对象后只留下内部字段，目标在下一帧失效。移动入口现在明确复制有限的 `x/z`，路线和存档也使用普通坐标。单兵连续点击、保持选择与途中保存均保留。
- 移除“西南据点”“撤退回家”“自动战斗”按钮、绑定和样式。拖动地图探索，点士兵选择、点空地移动、点敌人攻击。双方受击反击；当前有效目标保持稳定。手动移动优先，移动期间不反击；我方空闲时不主动搜寻敌人，敌方保留据点警戒及追击上限。
- 自动赴餐或补给途中受击会中断并反击，物资留在实际位置；玩家明确下达的赴餐移动优先。自动就餐条件改为体力低于 30%，且水平距离不超过 30 标准格；用 `GRID_SIZE` 换算，包含半径边界。只选已开启且可达的供餐火堆，手动进食仍可提前恢复生命和体力。
- 空火堆也可成为供餐目标。所有我方人类职业都能领取仓库木材/粮食，按原有批量运至火堆，再进食；动物等待供餐，骑手与马分别消耗餐份。军人不因此获得种植或建造资格。
- 共用经济系统的预留、仓库扣料、Goods、承运人、容量与交付结算，每个火堆同时最多一项补给。运输途中保存继续同一批物资；新移动/攻击中断运输时，货物留在真实位置，再接取不重复扣费。仓库存取仍触发开门。
- 玩家主动熄火不被自动开启。缺货、道路不通或他人正在配送时等待；路径重试受游戏计时限制。暂停冻结体力、燃料、烹饪、运输、战斗和恢复。

## 验证

- 类型检查、生产构建；逻辑测试 145 项通过。覆盖阈值和标准格半径、每个人类职业的补给进食、动物不能承运、共享预约、缺货、堵路、暂停、中断落地、读档、伤害与反击、实际位移及坐标序列化。
- 桌面与手机共 8 项相关浏览器案例最终通过（分批运行，失败项修正测试后重跑）：鼠标/触控的单兵连续移动及途中读档、步兵/骑兵自行补给后分别进食、独立攻击与离开交战、据点奖励不重复、领头气泡停止和手机/矮屏暂停居中。测试已移除旧按钮依赖，改用地图拖动；反击允许原待命单位进入交战；骑手与马等待各自的熟食份额后分别检查恢复。
- 实际查看桌面和手机截图，使用现有共享角色与原生动作播放；本次未改模型或新增进食/搬运动作。运输沿用现有资源表现与人物旁状态，进食保持待机姿态。已查看战斗、运输、进食和移动抵达截图，右下角仅保留恢复视角入口；手机密集交战时不同单位的标签仍可能互相遮挡。
