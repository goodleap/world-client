# 家园漫游 · 前端 Demo

Babylon.js + TypeScript + Vite 的 3D 前端技术演示。游戏使用独立的地图视角；角色与素材仍处于试样阶段，不代表正式游戏内容已完成。

## 运行

需要 Node.js 24 和 npm。在开发环境中执行：

```sh
npm ci
npm run dev
```

生产构建使用 `npm run build`，输出在 `dist/`。当前演示无需后端。

## 操作

- 启动先加载基础界面并进入菜单；菜单后台预加载引擎代码及人物资源，点击“开始游戏”复用已完成和正在进行的下载。菜单期间不创建 3D 场景或运行模拟；两段加载进度独立显示，资源加载失败可重新加载。加载详情列出引擎代码、每个模型的真实下载字节、解析、动作挂接、LOD、地图、材质/着色器及首帧状态；10 秒无新进展时指出等待项，未知大小明确标记。加载页和设置均可复制诊断。
- 主菜单分别提供“继续游戏”和“开始游戏”。有效存档可继续；没有或无法读取存档时禁用继续入口并说明原因。开始新游戏覆盖已有进度前使用原生确认对话框，取消保留原档；新场景成功打开后才保存新进度，加载失败不清空旧档。
- 游戏右上角显示 FPS 和 CPU 毫秒/帧，约每半秒更新；CPU 耗时测量游戏逻辑、渲染提交和标签更新，不使用帧间隔或 GPU 计时。
- 人物加载后将同骨架、同材质、同坐标空间的兼容部件合批，保留原始顶点、颜色和权重；原始人物 GLB 不变。细小花草使用较少的曲面细分，触屏地图使用 1024 阴影贴图并保留 PCF 柔化，人物查看模式及桌面为 2048。
- 点击人物或动物选中指挥单位；包括农民、士兵和狗，选中后点击空地均可寻路移动。选择本身不打断行为，新有效指令优先，完成后恢复自主行为。
- 点击土地、资源或建筑，只在对象附近显示操作按钮，不附加背景框、标题和关闭按钮；1 个单独显示，2 个左右并列，3～4 个排成两行。选中农民后点只有一种有效操作的目标直接指派作业，播种需先选择作物。指挥单位采用单次选择：再次点击同一人物取消，点击其他人物切换，移动或作业下令成功后自动取消选择；失败与等待作物选项时保留选择。取消选择不撤销指令。农民被移动或其他作业打断时保留原进度和材料，到达或完成新作业后继续工作。
- 右上角设置使用浏览器原生模态弹窗，打开时暂停游戏并阻止下层输入；操作说明可在其上打开。回到主菜单前保存并释放当前场景，再次进入从存档继续；网页版退出显示退出页，可自行关闭标签页。存储失败时保留当前游戏并提示重试。
- 鼠标和触屏拖动地图时，相机直接跟随输入，松手后停止；电脑也可使用 WASD 或方向键。
- 鼠标滚轮、双指捏合或右侧加减按钮缩放；罗盘查看全景，回转箭头恢复初始视角。
- 点击右侧“农”可放大查看农民模型及其基础行走动作，再次点击返回。
- 点击右侧“人”可近看新版基础人物的站姿；支持缩放，再次点击或拖动地图返回。
- 切换标签页、失焦或离开页面时暂停渲染、动作和模拟；返回后清除残留输入，不补算离开时间。操作说明等手动暂停保持原状态。

单位连续移动；寻路使用网格搜索作为路线计算工具，避开地图障碍。手动移动和农民赶路共用路线执行：遇到停留单位提前绕行，横穿或目标暂被占用时稳定等待，对向阻挡按固定顺序让行，保留原目标。等待播放待机，实际前进才播放奔跑；不逐帧左右试探。农民无任务时站立，其他单位在没有指令时继续在各自活动范围内漫步。作业按单位能力执行，当前经营作业由农民承担。

已核对 Babylon 9.32.1 的 Recast Crowd：它要求 Recast 依赖、导航网格和代理统一接管移动，无法直接叠加到当前按角色区分的农田通行规则、动态经营障碍及作业点路线。因此当前补充有限的路线重算/等待协调，继续复用原有寻路和 Babylon AnimationGroup；不新增碰撞或动画引擎。

所有有明确目的的移动使用奔跑。狗接受移动指令时使用 Babylon 原生 `DogRun` 配合现有骨架，闲逛保留原有步态；造型沿用现有素材。

人物行走、奔跑和干活动作均加快一倍，移速同步加快一倍（指挥基础人物奔跑约 5.00 世界单位/秒、骑兵约 6.96）。Walk／Run／RideWalk／RideRun 使用 Babylon AnimationGroup 按实际移速同步步频，干活 Hammer 以原来 2 倍频率播放；作业耗时和作物生长时间保持原值。基础模型、骨架与原始动作资源不变。

基础人物保留用户同意进入 Demo 的比例及后续头身饱满度改进，本轮细化圆润拳形与大小有别的脚趾；头部整体缩小 8%，使用 18 根基础骨骼和 2 根膝部变形辅助骨，文件与重建脚本见 [studies/base-human](studies/base-human/README.md)。自由漫步播放 `Walk`，选中后指挥移动播放独立的 `Run`，到达后回到自然站姿。奔跑先用固定骨架与脚掌代理验证连续轨迹，再绑定到模型；播放节奏与移速读取同一份动作参数。步兵已按原型重做并接入共享移动逻辑，见 [studies/soldiers](studies/soldiers/README.md)。骑兵复用基础骑手，搭配新马匹、鞍具、披风与长矛，移动使用独立的 RideWalk／RideRun，到达恢复骑乘站姿。弓兵也已复用同一人物与步态重做，使用木弓、斜背箭筒和羽箭；工人仍使用基础人物占位，并在名称中标记。农民直接复用同一基础人物、骨架和 Walk／Run，加上按原型制作的头巾、头发、服饰、靴子和农具，见 [studies/farmer](studies/farmer/README.md)；田园犬仍为早期 Demo 素材。人物受光已随场景校准，但这不表示旧角色造型通过了原型还原审查。

## 基础经营试运行

点击九块农田、树木、石材或两处建设用地，下达开垦、播种、收获、伐木、采石和建房任务。
一个农民按下达顺序接取可执行的任务，以共享 `Run` 奔跑前往，六种工作共用 `Hammer`，完成后站立或接下一单。有明确目的的移动（包括手动移动、自动前往作业点及返回未完成任务）统一奔跑，自主闲逛使用行走；赶路加快不缩短作业耗时。
材料不足、暂不可达会先处理其他任务；材料先预留，完工才扣除，取消会释放预留。仓储不足保留产出等待入库并释放农民。
树木、石材和作物采用 Babylon 原生实例；工作采用 AnimationGroup，沿用现有寻路、角色 LOD 和共享骨架，不修改基础人物资源。

时间、产量、库存上限和民房成本集中在 [economy-config.ts](src/game/economy-config.ts)，均为试运行数值。
进度只保存在当前浏览器，刷新会恢复，后台不生长或补算。民房目前展示建成结果，粮食仅入库；人口、粮食消耗、建筑升级、资源再生、多人协作和云端存档留待后续。

## 场景美术

以设计仓库原型中的游戏效果、自然植物和民房为参考，重制圆润树冠与连续分叉树干、弧形橙红瓦屋顶、奶油墙面、青绿色门窗及圆润石材。草地和沙黄色小路使用确定性生成的细微色差，作物、小草和花朵用于补充原型中的色彩层次。

场景使用统一日光；建筑、人物、树木和作物投射并接收阴影，地面同步接收。采用保留小物体轮廓的 PCF 过滤（WebGL 1 使用 Poisson），侧向日照让投影在大头和屋顶旁可见。植物色阶与局部体积仍由材质及顶点颜色共同表达，人物保留自身肤色与服装配色。树根的碰撞范围同步新尺寸；相机操作、寻路和骨骼动作沿用已有逻辑。

源文件、重建方法和本轮审查范围见 [环境素材制作说明](studies/environment/README.md)。这些场景素材仍接受用户视觉评审，不代表整个游戏或全部角色已完成还原。

## 验证

```sh
npm run build
npm test
npm run test:e2e
```

浏览器测试会启动本地预览服务；若环境已安装 Chromium，可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定其路径。测试覆盖相机操作、桌面和手机点选、单位指令、绕障寻路、农民动画、居民漫步，以及后台暂停、恢复首帧和手动暂停保持。基础经营另有资源结算、材料预留、取消、容量、存档恢复及桌面/触屏流程检查。云端软件 GPU 的结果不能代替 iPhone 真机性能验证。

正式游戏设计以设计仓库中经确认的文档为依据。
