# 家园漫游 · 前端 Demo

Babylon.js + TypeScript + Vite 的 3D 前端技术演示。游戏使用独立的地图视角；角色与素材仍处于试样阶段，不代表正式游戏内容已完成。

## 运行

需要 Node.js 24 和 npm。在开发环境中执行：

```sh
npm ci
npm run dev
```

生产构建使用 `npm run build`，输出在 `dist/`。当前演示无需后端。

人物当前的统一制作与发布入口为 [studies/characters](studies/characters/README.md)。基础人体及 Walk、Run、Hammer、持械、骑手动作集中维护，职业引用共享部件；马使用独立骨架与动作。下文的旧制作目录保留历史说明，不再是公共人体或动作的独立更新入口。

## 首轮实时 PvE 战斗

依次点击步兵、弓兵或骑兵，单独指挥当前士兵。点敌人攻击、点空地移动；移动与攻击保留选中。切换士兵不取消前一人的命令。敌我受击反击，手动移动优先。小队、右下角战斗按钮及据点圆圈/旗帜已移除，通过拖动地图探索。

首轮敌方为两名近战和一名弓手。双方拥有生命、攻击、护甲、攻击间隔、射程和移速；近战分散接近，远程检查射程与遮挡，敌人有限追击。挥剑、射箭和骑乘刺击来自共享人物动作库的 SwordSlash／BowShot／LanceThrust，弓弦和搭箭跟随手部；伤害由游戏时钟唯一结算。敌我攻击间隔和动作按 3.5 倍试行节奏加快，计入模拟步进后持续攻频至少为旧版三倍。

我方战败后原地受伤，仍可缓慢移动到火堆进食，逐步补充体力与生命；不自动回家、不远程扣粮回满，无永久死亡。清理据点后生成木材 24、石材 16、粮食 12 的待搬运物资，须由农民送至仓库，受容量约束；附近建设限制解除。上述数值为试行参数，集中在 `src/game/combat-config.ts`。战斗、火堆、体力、恢复与奖励接入版本 8 存档，旧存档不迁移；暂停和后台停止整个游戏，返回后需手动继续。

实现说明、测试和实际渲染证据见 [首轮战斗验证](docs/combat/first-round.md)。

## 火堆与体力

建筑菜单可建造石圈火堆（试行成本 8 石材）。点火后农民从仓库分批配送木材和粮食，取货扣仓库、到货加入火堆本地库存；熄火不消耗，关闭烹饪只照明。火堆根据实际状态展示熄火、火焰、火焰加烤肉。附近照明最多使用两盏无阴影点光源。

人物和动物都有体力与生命，骑手和马分别记录。进食全自动，无手动进食按钮；已开启火堆 30 格内，体力低于 30% 或受伤的单位在当前任务完成后自动休整，手动移动、战斗、撤退优先。每份熟食在 6 游戏秒中逐步补充 45 体力、12 生命，低体力降低移动/工作效率并延长攻击间隔，零体力仍保留一半效率。数值均可调整，不代表最终平衡。

仓库实际存取时门会短暂打开、停留并关闭，连续存取延长打开；设置与后台同时暂停门、燃烧、烹饪与进食。火堆建造预留 2×2 格，建成后通行碰撞按真实石圈使用圆形。最新机制、证据和限制见[本轮交付记录](docs/combat-and-auto-feeding/implementation.md)。

## 操作

- 启动先加载基础界面并进入菜单；菜单后台预加载引擎代码及人物资源，点击“开始游戏”复用已完成和正在进行的下载。菜单期间不创建 3D 场景或运行模拟；两段加载进度独立显示，资源加载失败可重新加载。加载详情列出引擎代码、每个模型的真实下载字节、解析、动作挂接、LOD、地图、材质/着色器及首帧状态；10 秒无新进展时指出等待项，未知大小明确标记。加载页和设置均可复制诊断。
- 引擎尚未准备好时也会列出浏览器正在等待的 JavaScript 文件，10 秒无进度报告即可选择重新加载。模块下载中的字节明确显示未知，完成后通过原生 Resource Timing 记录文件大小、响应状态（浏览器提供时）和耗时；不额外 fetch 或重执行代码。见 [微信引擎加载反馈](docs/diagnostics/wechat-engine-loading-2026-10-31.md)。
- 主菜单分别提供“继续游戏”和“开始游戏”。有效存档可继续；没有或无法读取存档时禁用继续入口并说明原因。开始新游戏覆盖已有进度前使用原生确认对话框，取消保留原档；新场景成功打开后才保存新进度，加载失败不清空旧档。
- 游戏右上角显示 FPS、CPU 毫秒/帧和实际提交三角形/帧（含阴影），约每半秒更新；CPU 耗时测量游戏逻辑、渲染提交和标签更新，不使用帧间隔或 GPU 计时。
- 设置中可复制最近 10 秒的性能诊断，包含原生 GPU 耗时（可用时）、绘制次数、提交面数、阴影、分辨率、LOD 和资源数量；GPU 计时不可用不代表未使用 GPU。手机地图阴影使用 Babylon 独立 LOD 相机与保守的静态投影体过滤，人物查看模式保持完整细节；测量依据和真机待确认项见 [手机缩放性能排查](docs/performance/zoom-2026-10-31.md)。
- 人物及 LOD 使用两个共享 GLB，合计 26.09 MiB，替代原来 10 个合计 65.93 MiB 的重复导出。原始顶点、颜色、权重、材质和动作轨道保持一致；原生资源容器只解析一次，每个人物拥有独立的姿势和动画播放状态。兼容部件合批后仍共享几何。细小花草使用较少的曲面细分，触屏地图使用 1024 阴影贴图并保留 PCF 柔化，人物查看模式及桌面为 2048。
- 点击人物或动物选中指挥单位；包括农民、士兵和狗，选中后点击空地均可寻路移动。选择本身不打断行为，新有效指令优先，完成后恢复自主行为。
- 点击土地、资源或建筑，只在对象附近显示操作按钮，不附加背景框、标题和关闭按钮；1 个单独显示，2 个左右并列，3～4 个排成两行。选中农民后点只有一种有效操作的目标直接指派作业，播种需先选择作物。再次点击同一人物取消，点击其他人物切换；移动和战斗攻击保留选择，生产作业下令成功后释放选择，失败与等待作物选项时保留选择。取消选择不撤销指令。农民被移动或其他作业打断时保留原进度和材料，到达或完成新作业后继续工作。
- 右上角设置使用浏览器原生模态弹窗，打开时停止渲染与模拟并阻止下层输入。可调整环境补光、太阳光强度（0–2）和太阳光颜色，开关阴影或恢复默认光照；修改时仅刷新必要画面，偏好在当前浏览器保存。操作说明可在其上打开。回到主菜单前保存并释放当前场景，再次进入从存档继续；网页版退出显示退出页，可自行关闭标签页。存储失败时保留当前游戏并提示重试。
- 鼠标和触屏拖动地图时，相机直接跟随输入，松手后停止；电脑也可使用 WASD 或方向键，以固定 14 世界单位/秒平移，为原来的两倍，不随缩放变化。
- 电脑触控板双指滑动平移、捏合缩放；鼠标普通滚轮缩放，手机双指捏合缩放。右下角回转箭头恢复初始视角；操作说明在设置中查看。浏览器没有精确设备类型，按滚轮事件模式识别触控板与普通滚轮。
- 点击右侧“农”可放大查看农民模型及其基础行走动作，再次点击返回。
- 点击右侧“人”可近看新版基础人物的站姿；支持缩放，再次点击或拖动地图返回。
- 切换标签页、失焦或离开页面时暂停渲染、动作和模拟；返回后仍停在设置，需手动点击“继续游戏”，关闭弹窗或 Escape 不会自动恢复；清除残留输入，不补算离开时间。

单位连续移动；寻路使用网格搜索作为路线计算工具，避开地图障碍。手动移动和农民赶路共用路线执行：遇到停留单位提前绕行，横穿或目标暂被占用时稳定等待，对向阻挡按固定顺序让行，保留原目标。等待播放待机，实际前进才播放奔跑；不逐帧左右试探。农民无任务时站立，我方参战士兵待命并受击反击，敌方保留警戒索敌，狗仍在活动范围内漫步。作业按单位能力执行，当前经营作业由农民承担。

已核对 Babylon 9.32.1 的 Recast Crowd：它要求 Recast 依赖、导航网格和代理统一接管移动，无法直接叠加到当前按角色区分的农田通行规则、动态经营障碍及作业点路线。因此当前补充有限的路线重算/等待协调，继续复用原有寻路和 Babylon AnimationGroup；不新增碰撞或动画引擎。

所有有明确目的的移动使用奔跑。狗接受移动指令时使用 Babylon 原生 `DogRun` 配合现有骨架，闲逛保留原有步态；造型沿用现有素材。

人物行走、奔跑和干活动作均加快一倍，移速同步加快一倍（指挥基础人物奔跑约 5.00 世界单位/秒、骑兵约 6.96）。Walk／Run／RideWalk／RideRun 使用 Babylon AnimationGroup 按实际移速同步步频，干活 Hammer 以原来 2 倍频率播放；作业耗时和作物生长时间保持原值。基础模型、骨架与原始动作资源不变。

基础人物保留用户同意进入 Demo 的比例及后续头身饱满度改进，本轮细化圆润拳形与大小有别的脚趾；头部整体缩小 8%，使用 18 根基础骨骼和 2 根膝部变形辅助骨，文件与重建脚本见 [studies/base-human](studies/base-human/README.md)。自由漫步播放 `Walk`，选中后指挥移动播放独立的 `Run`，到达后回到自然站姿。奔跑先用固定骨架与脚掌代理验证连续轨迹，再绑定到模型；播放节奏与移速读取同一份动作参数。步兵已按原型重做并接入共享移动逻辑，见 [studies/soldiers](studies/soldiers/README.md)。骑兵复用基础骑手，搭配新马匹、鞍具、披风与长矛，移动使用独立的 RideWalk／RideRun，到达恢复骑乘站姿。弓兵也已复用同一人物与步态重做，使用木弓、斜背箭筒和羽箭；农民·领头与普通农民使用同一套农民服饰、骨架和作业动作，独立占位工人已移除。农民直接复用同一基础人物、骨架和 Walk／Run，加上按原型制作的头巾、头发、服饰、靴子和农具，见 [studies/farmer](studies/farmer/README.md)；田园犬仍为早期 Demo 素材。人物受光已随场景校准，但这不表示旧角色造型通过了原型还原审查。

## 家园自动经营

地图采用 100×100 标准格，中央小屋和仓库、四周混合树石、东侧曲线湖岸、东南农田及外延曲线路面。基础人物站宽固定换算为 1.1256098747 引擎单位，格宽为其 1.5 倍；种植与建筑共用网格，人物自由移动。手机默认横向约 10 格。

开局有小屋、仓库和三名农民，其中农民·领头额外具有领头效果。领头和普通农民一样参与耕种、采集、建造与运输，接受玩家的移动和作业指令，同时指挥农民经营小屋周围 30 格，名字前显示金色领头标记。领头效果独立于职业，后续职业领头也沿用普通角色加领头效果的设计，不创建独立工种或另一套人物资源。自动选择胡萝卜和小麦，经营范围内已开垦的农田；每座建成的仓库增加木材/石材容量各 2000、粮食 4000，尚有容量和可执行作业时继续生产，并计入在途、地面和已安排的预期供应，避免过量生产。领头只在有人空闲时下达实际任务，不提前批量排单。选中领头后可在左下角开关“开启领头指挥”，开关随存档保存；关闭后不再自动创建任务或指挥发言，并立即清除当前和排队的指挥气泡；领头仍能与普通农民一样工作，已接受的任务继续执行。

左下角建筑菜单提供耕地、仓库、火堆、民房，支持点选后放置及拖放。耕地占 1×1 格，开局 12 格均已开垦；新增耕地可紧邻扩展，放置后由农民执行开垦，无材料消耗，取消未完成的开垦会释放用地。仓库占 3×2 格、需木材 24 和石材 16；民房占 2×2 格、需木材 12 和石材 8。仓库完工后农民可选择较近且可到达的交货点，库存共享。

农业流程为开垦、播种、独立成长、收获、运输入库和复种。所有作业复用 Hammer，赶路复用 Run。首次开垦后保留耕地。资源完成采收后生成唯一地面产出，农民抵达仓库门口交付后才成为可用库存；没有携带模型。通常由刚完成采集的农民接着把这批资源送回仓库，无需重复下令，手动采集和领头派工相同。运输中断时保留当前位置和数量；仓库满时等待容量，交付时容量不足的余量留在门口。

玩家指令优先，移动、攻击成功后保留单位选择，生产作业安排成功后释放选择；切换或取消选择不取消已下达的命令。作业完成后恢复自动经营。选中人物/动物/物体使用统一浅青色轮廓高亮，地块和建筑显示与实际占地一致的覆盖及边框，切换/取消清除旧效果。不在作业按钮下另列领头状态。生长、放置失败等简单提示跟随操作目标并优先显示在其上方，避开固定控件；系统性问题在相应面板内提示。

首轮战斗后存档采用第 6 版结构，不迁移旧版，保存在当前浏览器，包含自建耕地与建筑坐标、成长、任务进度、资源、运输、居民位置/手动目的地和领头调度状态；回主菜单再继续可以接续。暂停和后台不推进经营，不补算离线时间。自动模式不代表引入人口消耗、资源再生或云端存档。

参数集中在 `world-data.ts`、`economy-config.ts`、`steward.ts`。完整经营与交互验证按实际流程执行；云端软件 GPU 不能代替手机真机性能和模型视觉验收。

## 场景美术

2026-11-01 按用户确认的方向将自然湖岸、变宽道路、混合树石和地表纹理直接用于默认地图，并扩展外围资源簇；不再提供独立样板入口或样板存档。采用固定种子，保留原有 3D 人物。范围、原生引擎实现与实际渲染复现方式见 [地图与光照](docs/map-and-lighting.md)。

以设计仓库原型中的游戏效果、自然植物和民房为参考，重制圆润树冠与连续分叉树干、弧形橙红瓦屋顶、奶油墙面、青绿色门窗及圆润石材。草地和沙黄色小路使用确定性生成的细微色差，作物、小草和花朵用于补充原型中的色彩层次。

场景使用统一日光；建筑、人物、树木和作物投射并接收阴影，地面同步接收。采用保留小物体轮廓的 PCF 过滤（WebGL 1 使用 Poisson），侧向日照让投影在大头和屋顶旁可见。植物色阶与局部体积仍由材质及顶点颜色共同表达，人物保留自身肤色与服装配色。树根的碰撞范围同步新尺寸；相机操作、寻路和骨骼动作沿用已有逻辑。

源文件、重建方法和本轮审查范围见 [环境素材制作说明](studies/environment/README.md)。这些场景素材仍接受用户视觉评审，不代表整个游戏或全部角色已完成还原。
