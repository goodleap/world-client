# 环境素材制作说明

本轮依据设计仓库的“地形植物资源农作物”“建筑与设施”原型，以及角色原型图中的“游戏内效果示意”，改善 Demo 的柔和卡通造型、色彩和受光。原型图片继续由设计仓库维护，不复制到公开前端仓库。

## 制作与运行

- `src/game/tree.ts`：不对称圆润树冠，黄绿色顶部、鲜绿中间色与深绿底部；通过不同规模与轻微色调变化复用同一树种。
- `build_tree_trunk.py`：用 Blender 4.3 的曲线、体素融合和平滑生成连续树干与根部，输出 `src/game/tree-trunk.json`。这份 JSON 是自制网格数据，运行游戏不需要 Blender。
- `src/game/environment-shapes.ts`：圆角轮廓与连续法线的基础形体、圆润植物体块及高度色阶。
- `src/game/buildings.ts`：弧形瓦片屋顶、奶油墙面、门窗、木框与石材。门洞宽高按当前人物尺度安排。
- `src/game/world.ts`：确定性绘制的草地与沙土色差、圆润作物、石岸、水面、小草和花朵；地图逻辑与可行走地形仍由 `world-data.ts` 管理。
- `src/game/lighting.ts`：统一日光、补光与模糊地面投影。树冠和屋瓦通过形体与材质表达局部明暗，避免小曲面自阴影产生错误色带。

从仓库根目录重新生成树干：

```sh
blender --background --factory-startup --python studies/environment/build_tree_trunk.py
```

此命令只用于素材制作。模型由本项目脚本生成，未使用外部素材或 Blender 插件，也未给客户端增加依赖。

## 树木远景 LOD

树木使用 Babylon 的原生屏幕占比 LOD；同一色调、材质、细节等级仍共享实例绘制。近景保留原始树干和六瓣树冠，中景每棵从 26,508 个三角形降至 5,306 个，远景为 1,326 个。各级保留六瓣树冠、树根和分叉，选择及伐木仍使用原来的资源实例。

树干中远景数据在开发阶段用 Babylon `QuadraticErrorSimplification` 生成，手机运行时不做网格简化。更新原始树干后，在仓库根目录执行：

```sh
node tools/build_tree_lod.mjs
```

手机阴影通道的独立 LOD 相机同步日光实际正交投影范围，使阴影细节与整张阴影贴图的覆盖范围一致。近景主画面及模型预览继续使用自己的相机选级。

Babylon 9.32.1 的 WebGL 默认共用实例通道缓存；独立阴影相机与主相机选择不同 LOD 时，会在混合大小的树木中重复提交部分实例。树木初始化时启用引擎已有的分通道缓存（WebGPU 的默认路径）；该开关尚无公开 API，集中封装于 `attachTreeLOD`，浏览器验证检查每个通道内没有重复实例。升级引擎时须复核此适配。

本地验证命令（先启动 Vite；可用 `REVIEW_DEVICE=mobile` 或 `desktop` 单独检查）：

```sh
REVIEW_ORIGIN=http://127.0.0.1:5173 node tools/review_tree_lod.mjs
```

验证脚本记录实际 WebGL 绘制调用，并与界面所用的原生三角形计数核对；检查全图树木及阴影实例数量、资源拾取、伐木移除、其他树木继续显示，以及正面、侧面、游戏视角的近中远景对比。脚本访问场景的入口只注入本地开发响应，不进入发布代码。

2026-10-31，同一初始存档、手机画幅 393 × 754、绘制尺寸 589 × 1131、全图缩放约 168 的对比：总提交从 8,146,050 降至 1,498,002 个三角形，其中树木主画面加阴影从 6,998,112 降至 350,064；总绘制调用保持 421。关闭阴影独立比较主模型，三个近景角度的像素均一致。此数据来自云端软件 WebGL 的几何提交验证，不是 iPhone 帧率或发热实测，也不代表其他发展阶段的存档面数相同。

## 审查范围

先检查单棵树的正面、侧面、游戏角度与缩小效果，再检查民房及整张地图的 PC 和手机实际渲染。第一轮树根、分叉的拼接边界已通过融合网格修正；叶冠暗部过黑、墙面发灰和小曲面自阴影条纹分别修正，不能用构建通过代替这些检查。

本轮目标是环境的形体与色彩方向。树皮细纹、建筑木纹等仍作简化，场景布局属于操作 Demo。农民尚未换成新版基础人物，其他人类角色仍为明确标注的基础人物占位；未把这些内容标记为完整原型还原。最终视觉判断由用户评审。
